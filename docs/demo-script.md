# check@collect 完整演示脚本

演示人：待团队指定。建议准备两条新 POI：一条用于整改，一条用于异议；不要改动已有最终裁定来模拟新流程。使用真实设备位置和现场照片。

## 准备

打开正式 HTTPS 入口，确认应用、数据库、RabbitMQ、OCR 正常。准备采集者、核验者、第三方、管理员四个独立账号；使用不同浏览器会话避免串号。先核对 /api/me 中的身份与角色。首次密码需修改。不得在投屏中展示密码或密钥。

## 主流程（约 10 分钟）

| 步骤 | 操作人和动作 | 应展示的结果 |
| --- | --- | --- |
| 1 | 管理员向采集者发布交通管制公告 | 采集者收到，核验者不被误发 |
| 2 | 采集者手机新增 POI，拍招牌，授权设备定位，OCR 识别，确认分类描述后上传 | 照片、定位精度、识别文字、POI 详情；无需手填坐标 |
| 3 | 核验者打开新数据通知 | 跳到实际 POI；核对类别筛选和地图点位 |
| 4 | 核验者标识错误并填写具体说明 | 错误单保存，采集者收到通知；地图显示错误进展 |
| 5 | 采集者按要求重新拍照定位并提交整改 | 新版本、历史照片及待复核状态可见 |
| 6 | 核验者确认整改 | 错误单解决，地图进展更新 |
| 7 | 另一条 POI 标错，采集者说明理由后驳回 | 状态有异议；双方进入同一私聊交流 |
| 8 | 一方提交无法达成共识的异议 | 第三方收到任务；无可用人员时由管理员分配 |
| 9 | 被指派第三方到现场拍照定位，填写裁定理由并提交 | 现场证据、最终有效版本、任务完成和最终裁定可见 |
| 10 | 当事双方查看通知与详情 | 双方均收到最终结果；原双方不能改写该次裁定 |
| 11 | 分别在采集者群和核验者群发言 | 两个独立角色群、消息刷新后保留 |
| 12 | 从地图选择 POI，获取起点并计算路线，再调起手机导航 | 步行/驾车距离、步骤和正确目标位置 |

## 平台与异常补充（约 3 分钟）

- 微信（真机局域网验收方式，2026-11-12 已跑通）：
  1. 电脑起应用（示例端口 8081），手机与电脑连同一 Wi-Fi；小程序改动 `miniapp/app.js` 的 `apiBase` 为 `http://<电脑局域网IP>:8081`，或用 `preview-context.js` 在打包时注入。
  2. 已登录账号在“我的账号”发起绑定，用开发者工具生成携带本次 ticket 的预览码（`scripts/wechat-preview.ps1`），手机扫码后直接点“确认微信身份”，无需输入配对码；`/api/me` 应显示 `wechatBound=true`。
  3. 退出登录后重复同一流程，会话应被微信直接建立为同一账号（userId 不变），全程不输入密码。
  4. 首次扫码且该微信尚未绑定账号时，小程序会转为注册表单：填写账号名与密码后创建**采集者**账号并绑定，浏览器随即完成登录；核验者、第三方与管理员仍只能由管理员分配，不能自助选择。
  平台限制：个人主体调用 `getwxacodeunlimit` 返回 85412，手机预览请求需要已备案的 request 合法域名，因此这条是开发/体验版验收路径，不是公众扫码入口；演示时如实说明，不用密码登录冒充微信登录。
- 拒绝设备定位：保留照片并提示授权/重试，不上传缺少位置的数据。
- 权限：普通账号不能读其他错误单私聊、不能提交他人的现场任务。
- 现场时间允许时展示 RabbitMQ 失败补投；已有记录不能表述为本场刚执行。
